# 模型结构化响应与核验恢复修复 — 0.5.1

日期：2026-10-18。仅修改 backend/ 与 docs/，未修改前端或自动重跑真实任务。

## 已定位的事实与限制

截图对应的历史任务已生成初稿，在独立 Fact Reviewer 调用后因结构化结果未通过暂停。旧代码不留存原始坏响应或具体校验错误，因此无法追溯确认该历史响应究竟是字段、JSON、空输出还是截断问题；不能把某个猜测当成已证实根因。

已确认两个实现问题：
1. 重试只增加泛化提示，没有上一答案及具体校验错误，且即使截断仍使用相同预算。
2. 生成→核验共用原写稿恢复位置，核验失败仍返回 plan_ready，导致前端显示“图文生成已暂停”并引导重新写稿。

## 修复

- 保留严格 JSON Schema 校验，不转换错误枚举、字符串布尔值或缺失字段。
- 支持 text/output_text 内容块及完整 JSON 代码围栏；不从任意说明文字中静默截取 JSON。
- finish_reason=length/max_tokens/max_output_tokens 均视为截断，哪怕文本看似完整也不采用。
- 重试携带上一答案及准确字段路径、错误类型和允许枚举；空输出/截断时增大预算。默认仍为6000，最多两次调用，此路径第二次12000；不全局提高正常请求预算。
- 失败原始输出、校验原因、finish_reason、usage、预算存于 Git 忽略的 .local/llm_diagnostics/{诊断编号}.json。不保存输入任务、请求头、密钥或图片 base64。界面显示阶段、具体原因与诊断编号。
- 核验开始前保存 resume_status=needs_review；失败保留初稿，可只 POST /api/tasks/{id}/review {version}。
- 历史核验失败记录通过 GET task 的只读恢复位置投影兼容；数据库原记录和历史不自动改写。旧报错说明初稿保留、无需重写。/review 同样识别该恢复位置，/confirm-plan 不再把这类错误当成重新写稿。
- 没有生成初稿的写稿失败仍停 plan_ready，不把它伪装成可核验状态。
- 模型接口返回 pre_consume_token_quota_failed / insufficient_quota / insufficient_balance 时，明确提示对应写作或核验密钥“API预扣额度不足”，不回显服务商包含密钥片段的错误正文，不自动重试额度错误。

## 当前外部限制

只发送人工合成数据的协议测试曾获得 HTTP 200、有效 Review JSON；之后测试12000/24000预算时收到403，服务商错误码 pre_consume_token_quota_failed、提示令牌额度不足。这证明对应请求无法完成预扣，不等于已查询账户余额为零；额度或可用密钥需要用户处理。未通过降低预算持续探测余额，默认预算恢复原值。

真实任务快照再次外发复现被自动审批拒绝（缺少本次真实内容再次出站授权），因此未执行。未发送真实文稿、配图或知识库原文进行隔离复现，也未自动核验或改写现有任务。历史坏响应根因仍待新的诊断记录或经明确授权的真实复验确认。

## 验证

新增21项合成故障回归；完整后端185项测试。覆盖：
- 无效枚举具体反馈、严格布尔校验、JSON格式、围栏、文本块；
- 截断即使JSON可解析也拒绝、重试预算增加、空输出、拒绝、两次失败仍阻塞；
- 私有诊断不包含密钥/输入内容，写日志失败不掩盖原错误；
- 历史核验错误只读投影、只重试Reviewer、保留稿件、未生成稿件不进入核验；
- 额度错误不盲重试且不泄漏服务商回显的密钥。
