# 手动补充文字依据

在“知识库依据 → 补充依据，再检查”选择“手动补充原文”，选择关联缺口，粘贴原文和来源 HTTP/HTTPS 链接。来源名称、配置说明可选。至少32字原文，最多20000字；链接只用于追溯，后台不访问网页。提交需明确确认，且绑定当前型号和版本。

## 接口

`POST /api/tasks/{tid}/manual-evidence`，202 后按原后台任务轮询。请求包含 version、product_id、request_ids、text、source_url、source_title（可选）、conditions（可选）、confirmed=true。版本过期409，范围或重复输入400，格式错误422。只允许已有资料和已确认结构化 Brief 的 plan_ready/needs_review/approved（包含相应可恢复错误）阶段。

每任务最多20份；原文按唯一 M… Source ID 保存，带原文哈希、提交时间、关联请求、source_type=user_manual、link_verified=false。来源名称省略时由链接域名生成。只有同一份最后提交的资料处理失败，才允许重试而不复制来源；已检查的重复原文提示不要重复提交。

## 检查与职责

保留已有原文和图片，与用户原文重新抽取事实、逐字定位摘录、检查需求覆盖与同配置冲突；不直接构造 supported，不重跑 Brief、不刷新 ZIP/ima。配置补充仅是用户说明，不替代原文证据。模型提取失败不采纳未经校验的新 Fact；原始补充仍保留。只有存在数据本身并不意味着已经独立核实来源真实性。

缺口或冲突仍在则暂停并保留双方来源；通过后检查既有图片，复用已核验素材，对尚未核验画面沿用 Asset Selector，再生成卖点建议等待确认。不会自动写稿，不增加图片。若已有已确认卖点，本次证据改变后旧规划和核验失效，历史仍可追溯。

手动补充仅用于当前任务，不修改本地 ZIP、云端 ima 或全局设置。刷新原资料源时重新附加本任务同型号补充；切换型号不会附加其他型号原文。执行舍弃范围原样保留，不因资料补全自动恢复此前明确舍弃方向。

## 来源限制

事实详情显示“用户补充，链接未独立验证”。Planner、Writer、Reviewer 均接收来源性质；最终报告 source_verification 记录限制，前端核验区显示提示。核验通过表示文章与所提供资料的一致性、引用和规则检查通过，不表示已联网验证原网页或原文真实性。

原“更新原资料源”入口不变。未自动发布公众号、写入知识库或创建真实产品参数；测试使用隔离示例。

## 部分支持与使用边界

coverage 新增 partial：复合检索问题未完整回答，但 fact_ids 保留可独立使用的原文事实。missing_details 与 usage_limits 面向工作人员，说明未知内容和不能扩展的结论。partial 不冒称完整回答。用户已确认提交的原文可作为任务依据，link_verified=false 不单独形成阻塞；原文中的“视频播放”“最长”“约”及具体版本等已知限定仍保留。不能把容量推成续航、视频播放推成办公时长，也不拼接不同配置。

一般 required 检索项不因部分缺失自动变为硬门槛；明确要求完整测试条件、真实 identity/safety/compatibility 门槛、事实冲突及无可用引用仍拦截。策略模型单独给普通卖点 waivable=false 不再阻止取舍；原有用户明确拒绝生成的条件及放宽确认仍保留。写作边界说明保存到 writing_boundaries 与 all_facts 追溯，不作为可宣传产品事实。

已有手动资料且尚无规划/正文的任务，可通过原 resume-plan 仅重评已存事实覆盖，保留全部来源与事实原文，不调用 Brief、不重新抽取、不重读ZIP/ima；覆盖通过后生成卖点建议，等待用户确认，不自动写稿。
