# 历史任务：效果与经验学习展示

本次只实现前端交互原型。真实任务记录沿用原接口，演示推文、指标、分析和匹配规则均在前端预置；没有新增后端接口、模型调用或真实 Writer 参考库写入。

## 预览与演示顺序

- 已运行的本地服务：http://127.0.0.1:5174/?preview=history-effects
- 实际工作台入口：http://127.0.0.1:5174/ → 历史任务 → 效果演示。
- 独立预览复用同一个 HistoryPage，仅开发模式启用，不需要后端服务。生产构建仍通过历史任务页进入。

建议用约一分钟演示：

1. 展示开学季、职场办公、差旅三个模拟推广任务；每个任务都有小红书、公众号和朋友圈内容。
2. 打开开学季小红书的“查看图文与效果”，查看全文、轮播图和表现快照。
3. 点击“加入优秀案例库”，等待本地模拟提炼，查看标题、开头、正文结构、语气和行动引导。
4. 点击“预览下次参考”，查看相同平台、相同场景匹配到的案例和可复用写法；切换平台可展示无匹配状态。
5. 关闭面板，在“优秀案例”筛选中找到收藏；刷新后仍保留。可移出案例，也可确认“重置演示”重新录制。

## 已实现的界面行为

- 任务记录和效果演示分开；真实记录没有虚构浏览量，也不会被当作演示收藏。
- 三个平台采用各自布局：小红书轮播、公众号段落内插图、朋友圈简短文本与图片网格。
- 展示模拟发布时间、指标来源和数据日期。朋友圈无浏览、收藏数据时用“—”；没有伪造发布链接。
- 手动加入优秀案例，显示预置分析；模拟处理期间有反馈，关闭面板会取消尚未完成的加入。
- 收藏后支持移除、平台筛选、优秀案例筛选和原文回看。未按指标自动判定优秀。
- 下次参考按已收藏案例的平台与场景精确匹配，呈现预置写法；不会提交新任务或改变真实 Writer 行为。
- 空收藏、筛选无结果、无匹配、本地存储损坏或不可用均有可继续操作的状态。
- 弹窗支持 Escape、焦点回退；手机布局优先呈现表现与收藏操作，内容可继续向下阅读。

## 数据与持久化

预置内容位于 src/historyEffectsData.ts，包含三个场景、九篇图文和九组写法说明。配图复用 public/planner-preview 下明确标注的示意插图，不是真实产品照片；演示正文不冒充知识库已验证参数。

收藏使用当前来源（协议、主机和端口）下的 localStorage，键为 hw-demo-history-cases-v1，格式为 {version:1,ids:[演示推文ID]}。只接受已知演示 ID，并支持多标签页同步。存储失败时保留当前页操作并提示可能丢失，不声称已持久保存。

“重置演示”只删除这一个键；保留真实任务、hw-last-task 和其他设置。跨浏览器、跨端口不共享收藏。未实现多用户、线上同步或真实数据采集。

## 文件组织

- src/HistoryPage.tsx：历史记录与效果演示视图、筛选和单一弹窗状态。
- src/HistoryPostDetail.tsx / HistoryPostPreview.tsx：全文、平台布局、指标与案例操作。
- src/ReferencePreview.tsx：下次任务的模拟匹配与写法展示。
- src/historyEffectsData.ts / useDemoCases.ts：预置数据与本地收藏。
- src/history-effects.css：页面、详情、手机适配样式。
- src/HistoryEffectsPreview.tsx：开发预览外壳。
- src/App.tsx / main.tsx：历史页懒加载与开发预览入口。
- qa/history-effects.spec.ts：隔离浏览器交互、存储、真实记录边界与无障碍测试。

## 后续接入边界

真实表现采集、真实发布时间和链接、案例分析生成、服务端案例存储、Writer References 检索加载均未实现。后续需要与后端另行确认接口，不能把本地收藏存在等同于真实 Writer 已学习。复用内容只应是写作方法；新任务的事实、价格、优惠及体验结论继续走原有证据与核验链路。

## 本地启动与验证

```powershell
npm --prefix frontend install
npm --prefix frontend run dev -- --port 5174
npm --prefix frontend run build
npm --prefix frontend run test:ui -- qa/history-effects.spec.ts
npm --prefix frontend run test:ui
```

浏览器测试沿用项目 Playwright 配置，默认使用本机 Edge。实际验证结果见 qa/QA_REPORT.md；截图与 JSON 报告保存在被 Git 忽略的 qa/screenshots/ 中。测试使用隔离模拟接口，不代表真实营销效果、模型写作质量或线上部署验收。
