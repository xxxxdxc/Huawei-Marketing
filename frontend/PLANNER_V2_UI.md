演示仅开发模式可用；所有事实、评分、推荐理由与SVG插图均为模拟。勾选、更新、保存、确认、恢复只操作本页状态，不发送API写请求，不调用模型。演示页展示如何使用交互，不证明真实策划质量。

## 当前交互

1. 候选排序区显示服务端分数、recommended/alternative推荐状态与理由、对应受众需求、原文、图片和限定条件。默认选用来自当前规划的selected_point_ids，不由前端按Top K重算。
2. 用户勾选只改变本地待更新集合。当前大纲的实际执行集合与待更新选择分开保存。选用变化时，旧大纲明确标为尚未更新，暂停编辑和确认；可撤销选用调整，无请求。
3. 点击“按所选卖点更新大纲”才POST /api/tasks/{id}/replan-points，body为{version,selected_point_ids,replace_current_plan:true}。有未保存编辑时先明确提示替换影响，允许取消。
4. 运行中保留原大纲只读可查。成功读取新规划，停在第二次规划确认；失败保留本地选择、未保存输入和原大纲，可重试或撤销选择后继续编辑。409保留输入，并要求显式载入最新版本。
5. 不再提供叙事框架名称或四选一下拉。只读折叠“为什么这样编排”使用composition_rationale，旧V2历史以narrative.ordering_rationale回退显示。
6. 段落可编辑标题（内部提示）、目的、读者问题、角色、篇幅预算、事实、图片及位置。段落卖点仅能从当前实际选用范围分配，保存段落不改变整篇selected_point_ids。候选覆盖与事实关联会给出本地提示，并由后端最终校验。
7. 图片顺序、平台图数与篇幅预算继续按项目约定展示。朋友圈默认1、小红书2–3、公众号3–4只是建议，前端不将其写成硬上限。
8. 手动编辑后，原候选评分仅作为生成时记录；不伪造新评分、事实通过或自动写作。

## 组件与状态

- PlannerAnalysis.tsx：推荐与备选、整篇勾选、原文和图片追溯、评分依据。
- PlanEditor.tsx：两种选择状态、显式更新、替换提醒、编排说明、段落与第二次确认。
- TaskView.tsx：重规划期间保留规划页及本地编辑，避免进度或版本变化造成输入丢失。
- plannerPresentation.ts：预算、候选关联提示与选择比较。
- PlannerPreview.tsx / plannerPreviewData.ts：开发专用隔离演示与版本恢复。
